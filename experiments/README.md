# EXIT Curve Experiments

All unsuffixed entropy/proxy columns are in bits. The default plots focus on
the X-error component, i.e. `H(x_E | E,S)` and `H(C_X | E,S)`, rather than the
joint `(x,z)` entropy. Columns ending in `_norm` are divided by `2n`; columns
ending in `_component_norm` are divided by `n` and are the right normalized
scale for a single CSS component.
Columns ending in `_logical_norm` are divided by `k` for one CSS component or
`2k` for the total correction class.

Main exact quantities:

- `exact_x_error`: `H(x_E | E, S) = |E| - rank(H_Z,E)`
- `exact_z_error`: `H(z_E | E, s_X) = |E| - rank(H_X,E)`
- `exact_error_total`: `H(x_E, z_E | E, S)`
- `exact_x_stabilizer`: `dim S_X(E)`
- `exact_z_stabilizer`: `dim S_Z(E)`
- `exact_x_class`: `H(C_X | E, S)`
- `exact_class_total`: `H(C | E, S)`; retained in the CSV for debugging but not used in the default plot.

Main peeling proxy quantities:

- `peel_x_unassisted_guess`: `H_peel(x_E | E, S)`
- `peel_stabilizer_found_total`: `dim S_X^peel(E) + dim S_Z^peel(E)`
- `peel_saved_guess_total`: `H_peel(x_E,z_E | E,S) - H_peel(C | E,S)`
- `peel_x_aided_guess`: `H_peel(C_X | E, S)`
- `dual_primal_residual_total`: `|R_X^dual+primal(E)| + |R_Z^dual+primal(E)|`

The stabilizer-aided guess reduction is reported as the difference between
the unassisted peeling guess entropy and the aided peeling guess entropy. In
the exact rank calculation, the corresponding identity is

`H(x_E,z_E | E,S) - H(C | E,S) = dim S_X(E) + dim S_Z(E)`.

For an erasure pattern with no erased logical ambiguity, `H(C | E,S)=0`.

The JSON output contains an `areas` block. For each curve, `endpoint_delta`
is the exact difference between the last and first sampled curve values, and
`trapezoid_derivative_area` is the numerical integral of the finite-difference
derivative column.

## Faster exact class modes

The script now has target-only exact class modes for runs that only need
`H(C_X | E,S)` or `H(C_Z | E,S)`.

```powershell
.\.venv\Scripts\python.exe experiments\exit_curve_experiments.py --code codes\gross_HxHzLxLz.npz --paired-derivative --exact-class-target-only --exact-class-component x --centered-ps --runs 1000 --plot
```

These modes use bit-packed GF(2) rows internally instead of dense sliced matrix
elimination. If `Lx`/`Lz` are present in the input `.npz`, the class entropy is
computed from the logical-rank formula

`H(C_X | E,S) = k - (rank([H_X,K; L_X,K]) - rank(H_X,K))`,

where `K` is the unerased set. If logical operators are absent, the code falls
back to the kernel/stabilizer rank identity, so a dense first-time `.npz` with
only `Hx` and `Hz` still executes.

Useful flags:

- `--exact-class-target-only`: compute only exact class entropy.
- `--exact-class-component x|z|both`: choose the class component.
- `--no-logical-rank-class`: force the fallback kernel/stabilizer rank formula.
- `--paired-derivative`: average per-sample finite differences.
- `--centered-ps`: use the sparse-at-edges p-grid.

In paired target-only mode, each Monte Carlo sample draws one threshold vector
and updates the erased mask incrementally as `p` increases, so the same nested
sample is reused for all p values.

Sparse HGP `.npz` files with COO arrays such as `rows_HX`, `cols_HX`, `n_HX`,
and `m_HX` are loaded directly into packed GF(2) rows for the target-only
exact-class modes. They do not need to be converted to dense `Hx`/`Hz` arrays.
Dense first-time `.npz` files still load through the original `Hx`/`Hz` path.

For the sparse HGP runs, `scripts/run_hgp_sparse_exit_batch.py` writes:

```text
<code>_exit_rule1.json / .csv / .png
<code>_exit_rule1_paired_derivative.json / .csv / .png
<code>_exit_rule1_hybrid_paired3.png
```

The hybrid three-panel PNG uses a wide p-grid for the bit-scale panel and the
15-point `[0.4, 0.6]` centered p-grid for the logical and paired-derivative
panels.

Sparse bivariate-bicycle code files can be generated with
`scripts/generate_bivariate_bicycle_code.py`. The generated files use the same
COO key convention (`rows_HX`, `cols_HX`, `n_HX`, `m_HX`, etc.) as the sparse
HGP files and can be run with `scripts/run_bb_sparse_paired_exit_batch.py`.
Their current `k` values and recorded distance upper bounds are listed in
`data/experiments/bb_code_parameters.csv`.

For the standard planar surface-code files generated by
`scripts/generate_surface_code.py`, `--surface-fast-x-class` is an additional
paired-derivative shortcut for large distances. It computes the one-sided
surface-code class event by top-to-bottom erased-edge connectivity rather than
by rank. This shortcut is specific to this surface-code layout.

## Beyond Pure Erasure

`experiments/beyond_erasure_diagnostics.py` is the first executable step toward
the broader EXIT/GEXIT program. It keeps the same correction-class entropy
language but replaces the pure-erasure rank quantity by a posterior quantity
conditioned on the full observation `Y` and syndrome:

- `posterior_x_error`: `H(x | Y,S)` in bits.
- `posterior_x_class`: `H(C_X | Y,S)` in bits.
- `posterior_x_degeneracy_gain`: `H(x | Y,S) - H(C_X | Y,S)`.

The script currently handles one CSS component at a time. For the X component,
it uses `H_Z` as the syndrome check and quotients by the X-stabilizer rowspace
of `H_X`; for the Z component, the roles are swapped.

The channel model is mixed erasure plus binary component noise:

```text
Pr(component error = 1) = 1/2 on erased qubits,
Pr(component error = 1) = p_error on non-erased qubits.
```

Setting `p_erasure=0` gives the biased CSS Pauli-component diagnostic. Setting
`p_error=0` recovers the pure-erasure component posterior.

Example quick run:

```powershell
.\.venv\Scripts\python.exe experiments\beyond_erasure_diagnostics.py --code codes\surface5_HxHzLxLz.npz --component x --runs 5 --p-erasure-grid 0 0.2 --p-error-grid 0 0.02 --max-exact-affine-dim 12 --approx-samples 200 --plot
```

For paper-facing values, inspect `exact_runs`, `list_runs`, and
`mean_affine_dimension` in the CSV/JSON. Rows where `list_runs > 0` are
list-restricted MCMC estimates, not exact ML posterior entropies. Exact
non-erasure enumeration is exponential in `mean_affine_dimension`; for example,
surface5 Pauli-only X-side samples have affine dimension 21, so exact runs
should be requested deliberately with `--max-exact-affine-dim 21` or higher.
